# 三人团队技术负责人：先学什么

目标：能解释系统如何工作，判断改动是否可靠，遇到故障能定位与恢复。每项都用这个项目练习，不必先完成一整套课程。

## 先做一次完整体验

1. 使用 Node 24，运行 `npm ci`、`npm run check`。
2. 按 [试点操作指南](pilot/OPERATIONS.md) 启动本地试点。
3. 登录，保存计划，上传模拟设备事件，创建并完成一次跟进。
4. 阅读 `src/lib/pilot/api.ts`，顺着一次请求找到权限判断与数据库操作。

## 必学顺序与验收

| 顺序 | 知识 | 项目练习 | 掌握标准 |
| --- | --- | --- | --- |
| 1 | Git：状态、diff、分支、提交、PR、revert | 新建分支改一条界面文案，运行检查，提交，再用 revert 撤销 | 能说明改了什么；不会用 reset/force push 掩盖问题；不提交 secrets |
| 2 | Web 数据流：浏览器、HTTP、JSON、API、数据库 | 用浏览器 Network 查看登录、读取计划、保存计划；跟踪到 `pilot/api.ts` | 能解释 400/401/403/409/429/503，并定位失败发生在哪一层 |
| 3 | TypeScript 与异步 | 读懂 `Device`、`Principal`、`Plan`，理解 `await`、Promise、异常与返回类型 | 能修改一个字段并同步修改校验、数据库、UI 和测试 |
| 4 | SQL 与数据模型 | 阅读迁移文件，查询一个设备的事件，查看计划旧版本与 audit | 理解主键、外键、唯一约束、索引和事务；知道为什么并发不能只靠“先查后写” |
| 5 | 登录与权限 | 用家庭 B 的凭证读取家庭 A；用设备凭证修改计划；轮换一个成员的 tokenHash | 能解释每种请求为什么应被拒绝；理解身份认证不等于数据访问授权 |
| 6 | 时间、重试与幂等 | 同一个 eventId 上传两次；同 ID 改内容；延迟补传旧事件；并发 tick | 能解释为什么记录只能有一份，为什么重试不能清除新提醒，为什么需要区分观察时间与接收时间 |
| 7 | 测试与发布 | 修改一项规则，先写反例，再修实现；执行 build 与本地 D1 联调 | 能判断测试是否验证业务后果；知道“编译通过”并不等于用户流程可用 |
| 8 | 监控、备份与回滚 | 找请求编号对应的日志，导出本地数据库，恢复到另一份本地库 | 能区分前端错误、数据库故障、设备离线、调度失败；能恢复而不丢新数据 |
| 9 | 数据与模型评估 | 比较固定提醒与个性化提醒，列出误报、漏报、数据泄漏和有效结果的定义 | 能解释开盒≠吞服、相关≠干预有效、合成数据分数≠真实效果 |

先完成 1–6，再逐步深入 7–9。每次只拿一个可运行的任务学习，比同时学习多个框架更有效。

## 推荐阅读（按需阅读相关章节）

- [Pro Git 中文版](https://git-scm.com/book/zh/v2)：起步、Git 基础、分支。
- [MDN HTTP 概述](https://developer.mozilla.org/zh-CN/docs/Web/HTTP/Guides/Overview)：请求、响应、状态码。
- [TypeScript Handbook](https://www.typescriptlang.org/docs/handbook/intro.html)：常用类型、类型收窄、函数。
- 本项目安装版本的 Next.js 指南：`node_modules/next/dist/docs/`。先看 Route Handlers、Authentication、Environment Variables；不要直接套用旧版教程。
- [PostgreSQL 入门](https://www.postgresql.org/docs/current/tutorial.html)：理解通用 SQL、关系与事务；本项目试点实际使用 D1/SQLite，执行语法以 D1 为准。
- [Cloudflare D1 数据库 API](https://developers.cloudflare.com/d1/worker-api/d1-database/)：prepared statements、batch 事务、迁移。
- [OWASP API Security](https://owasp.org/www-project-api-security/)：优先理解对象级权限与身份认证。

## 每次让 AI 修改代码后，你必须能回答

1. 这次解决的用户问题是什么？哪些行为改变了？
2. 数据存在哪里，谁可以访问？是否出现了新的 secret？
3. 断网、重试、重复点击、多人同时操作会怎样？
4. 哪些测试证明结果？还有哪些验证没有做？
5. 数据迁移后如何回滚？旧设备与旧客户端还能否使用？

不需要背下每行代码，但不要在无法解释上述问题时直接发布。

## 三个人的建议分工

- 技术负责人（你）：系统边界、数据模型、开发优先级、验收和发布。AI 可以承担实现、测试和文档，但上线判断由团队负责。
- 用户与试点负责人：招募、设置指导、反馈、异常原因确认，维护每周问题列表。
- 产品验收与合作负责人：按场景测试、记录复现步骤、使用说明、合作与付费意愿验证。

另外两位至少都应能完成首次设置、走通核心流程、提交“步骤＋预期＋实际＋时间/请求编号”的问题报告。只有你能写代码，不代表只有你能测试和排查。

## 可以后置

从零训练大模型、深度学习数学推导、Kubernetes、复杂微服务、多云部署。先把数据、权限、可靠性和实际使用效果做好。
